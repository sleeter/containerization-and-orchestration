# Skill: диагностика shop

## Назначение
Помогать дежурному инженеру сопоставлять состояние Kubernetes
и доступность сбора метрик Prometheus. Только чтение данных.

## Toolkit
Все инструменты вызываются без аргументов: область проверки
зафиксирована в конфигурации серверов.

- prometheus_targets — Prometheus MCP; возвращает up для shop.
- kubernetes_pods — Kubernetes MCP; возвращает имена, phase и
  conditions незавершённых подов api и worker.
- kubernetes_deployments — Kubernetes MCP; возвращает имена,
  желаемое число реплик и status Deployment в shop.

## Порядок действий
1. Вызвать все три инструмента.
2. Раздельно разобрать api и worker.
3. Сравнить spec.replicas, readyReplicas и availableReplicas.
4. Проверить condition Ready у подов.
5. Сопоставить эти данные с up, учитывая разное время снимков.
6. Выдать факты с источниками, ограничения и гипотезы отдельно.

## Правила доказательности
- up=0 означает ошибку scrape, а не доказанное падение приложения.
- Running не означает Ready.
- Отсутствующее поле означает неизвестность, а не нулевое значение.
- Без restartCount нельзя утверждать отсутствие перезапусков.
- Количество готовых реплик не доказывает принадлежность подов
  текущему ReplicaSet.
- batch с spec.replicas=0 не считать неисправностью.
- Не выдумывать показатели HTTP-ошибок, задержек и результаты команд.
- Гипотезы не выдавать за найденную причину.
- Предложенные команды не считать выполненными.
- Не изменять ресурсы и не запрашивать Secrets.

## Результат
Краткий отчёт: подтверждённые факты, ограничения данных,
гипотезы и следующие проверки.
